## 1. 变更提案（Bug 背景）

> 对应传统文档：缺陷报告 | 职责：现象、目标、影响范围、验收标准

### 1.1 背景与动机

v1.0.16 把会话列表改为「置顶 / 非置顶」双标签页，非置顶页按本地自然日分组，分组可点击收起展开，默认只展开最近一天。

**缺陷现象**（用户报告，v1.0.17 修复前）：

> 分组列表数据是又了，但是分组点击展开收起没又效果啊

即：分组标题、日期标签、每组条数都正确渲染，但点击组头（无论哪一组）没有任何变化——箭头不变、条目不增减、列表高度不变。无报错、无控制台日志。

### 1.2 变更目标

| # | 目标 |
|---|------|
| 1 | 点击组头能在展开 / 收起之间切换，箭头随状态在 `▾` / `▸` 之间变化 |
| 2 | 收起时该组条目从 DOM 移除（条件渲染，而非 CSS 隐藏） |
| 3 | 保持既有语义不变：默认只展开第一个分组；用户显式点过的分组按日期键记忆 |
| 4 | 不改变已正常工作的部分：分组顺序、组内顺序、跨组连续序号、标签页切换、全选作用域 |

### 1.3 影响范围

| 维度 | 结论 |
|------|------|
| 首次引入版本 | v1.0.16（双标签页 + 日期分组的同一次提交 `f8cbd16`） |
| 受影响功能 | 仅「分组折叠交互」。分组渲染、置顶徽标、标签页计数与切换、全选、导出/删除均正常 |
| 是否影响数据 | 否。纯视图层状态，不触碰 `selected` / `sessions`，与导出、删除链路无交集 |
| 降级表现 | 折叠失效时退化为「所有分组始终按默认规则展开」的静态列表，不会报错、不会误删或误导出 |

### 1.4 风险评估

| 风险 | 等级 | 说明与缓解 |
|------|------|-----------|
| 修复引入重建导致行内选中态丢失 | 低 | `DateGroupPanel` 只包裹渲染结构，`SessionItem` 的选中态读 `selected` signal，组件重建不影响语义 |
| `computed` 在组件内存活导致泄漏 | 低 | 与既有 `allChecked` 同款用法；`when()` 负责释放，且分组数量为个位数 |
| 分组默认展开判定依赖下标 `index` | 低 | 与修复前一致：列表重排后「第一组」可能换人。属已知设计取舍，见 change 提案 §2.4.4 |
| 真机与 mock 环境行为不一致 | 低 | 折叠逻辑与 `chrome.*` 无关，纯 DOM/响应式；mock 环境已覆盖真实交互路径 |

### 1.5 验收标准

| # | 验收项 | 判定方式 |
|---|--------|----------|
| 1 | 点击已展开的组头 → 收起 | 该组 `.session-item` 数量变为 0，箭头变 `▸` |
| 2 | 点击已收起的组头 → 展开 | 数量回到组内总数，箭头变 `▾` |
| 3 | 默认状态 | 仅第一个分组展开，其余收起 |
| 4 | 状态记忆 | 切换标签页再切回，先前手动设置的分组状态保持 |
| 5 | 计数不受影响 | 收起后组头数量标签仍显示组内总数 |
| 6 | 无回归 | 标签页切换、全选、序号连续、徽标显示均与 v1.0.16 一致 |

## 2. 技术方案

### 2.1 根因分析

**问题代码**（v1.0.16，`SessionListPanel` 内）：

```tsx
dateGroups().map((g, gi) => {
  const expanded = isGroupExpanded(g.key, gi);  // ← 在这里求值成普通布尔
  return (
    <div class="date-group">
      <div class="date-group-header" onClick={() => toggleGroup(g.key, gi)}>
        <span class="date-group-arrow">{expanded ? '▾' : '▸'}</span>
        ...
      </div>
      {expanded ? g.items.map(...) : null}
    </div>
  );
});
```

**编译产物**（`dist/popup/main.js`，问题版本）：

```js
each(__f42, () => dateGroups(), (g, gi) => {
  const expanded = isGroupExpanded(g.key, gi);   // 一次求值，得到常量
  ...
  when(__el46, () => expanded, () => { ... '▾' ... }, () => { ... '▸' ... });
  when(__el44, () => expanded, () => { each(...) }, () => { ... });
```

三条关键事实：

| # | 事实 | 后果 |
|---|------|------|
| 1 | `each(src, () => dateGroups(), cb)` 只订阅 `dateGroups`，`cb` 仅在分组集合变化时重跑 | 点击组头不改变 `dateGroups`（它只依赖 `sessions`），`cb` 不会重跑 |
| 2 | `isGroupExpanded()` 内部虽然读了 `groupExpanded()`，但这次读取发生在 `each` 的回调体内，而不是在 `when` 的 getter 内 | 该读取没有被任何存活 effect 追踪 |
| 3 | `when(el, () => expanded, ...)` 的 getter 返回闭包常量 | getter 不读任何 signal → 依赖集为空 → `groupExpanded.set()` 永不触发它 |

于是形成闭环：**点击 → `groupExpanded` 变化 → 无人订阅 → DOM 不动**。数据侧一切正常，正好对应「分组有了，但点了没反应」。

补充：`isGroupExpanded` 本身是正确的纯函数，问题不在它，而在**调用位置**——在渲染回调体里调用，等于把响应式读取从追踪范围内搬了出去。

### 2.2 修复方案（ADR）

**方案 A（采用）：抽 `DateGroupPanel` 组件，用 `computed` 承载派生状态**

```tsx
function DateGroupPanel(props: { group: DateGroup; index: number }) {
  const g = () => resolve(props.group);
  const index = () => resolve(props.index);
  const expanded = computed(() => isGroupExpanded(g().key, index()));

  return (
    <div class="date-group">
      <div class="date-group-header" onClick={() => toggleGroup(g().key, index())}>
        <span class="date-group-arrow">{expanded() ? '▾' : '▸'}</span>
        <span class="date-group-label">{g().label}</span>
        <span class="date-group-count">{g().items.length}</span>
      </div>
      {expanded() ? g().items.map((s, i) => <SessionItem session={s} index={g().start + i} />) : null}
    </div>
  );
}
```

编译产物（修复后）：

```js
const expanded = computed(() => isGroupExpanded(g().key, index()));
when(__el19, () => expanded(), ...);   // ← getter 调用 computed，依赖成立
when(__el17, () => expanded(), ...);
```

`when` 的 getter 读 `expanded()` → `computed` 读 `groupExpanded()` → 订阅建立。`groupExpanded.set()` 后 computed 失效，两个 `when` 重新求值。

**方案 B（否决）：内联到 JSX 表达式，不在回调体里赋 `const`**

```tsx
{isGroupExpanded(g.key, gi) ? '▾' : '▸'}
{isGroupExpanded(g.key, gi) ? g.items.map(...) : null}
```

同样可行（getter 内直接调用函数），但箭头与内容各读一次 signal，且仍暴露在 `map` 回调体里，后来者容易再犯「提前求值」的错。可读性和防回归性都不如 A。

**方案 C（否决）：改为 `key` 驱动让 `each` 重跑**

例如把展开状态揉进 `dateGroups` 的 computed，使 `each` 的依赖包含折叠状态。代价是分组数据与视图状态耦合，`start` 偏移需重算，属于为绕过框架机制而扭曲数据模型。

**顺带简化**：`toggleGroup` 原手写「未记录则按第一组展开」的三元判断，与 `isGroupExpanded` 重复，改为直接复用：

```tsx
function toggleGroup(key: string, index: number) {
  // 在事件处理器里读取 signal 不会建立订阅，peek 与内联读取取到的都是最新值
  groupExpanded.set({ ...groupExpanded.peek(), [key]: !isGroupExpanded(key, index) });
}
```

## 3. 增量规范（修复后契约）

### 3.1 派生状态契约：signal 读取不得脱离响应式上下文

| # | 规则 | 反例 | 正例 |
|---|------|------|------|
| 1 | 依赖 signal 的派生值，必须在 `computed` 内计算，或在 JSX 表达式（`when` 的 getter）内现场调用 | `const x = f()` 在 `map`/`each` 回调体内 | `const x = computed(() => f())` |
| 2 | 事件处理器内需要读取最新值时用 `peek()` 或直接读取（不建立订阅） | — | `groupExpanded.peek()` |
| 3 | 子组件的动态 props 是 getter，必须经 `resolve()` 解包 | `props.group.key` | `resolve(props.group).key` |
| 4 | 视图状态与数据模型分离：折叠状态不进 `dateGroups` | — | `dateGroups` 只依赖 `sessions` |

### 3.2 边界条件矩阵

| 场景 | 期望行为 | 实测 |
|------|----------|------|
| 默认加载 | 仅第一个分组展开 | ✅ |
| 点击首个（已展开）组头 | 收起，条目 2 → 0，箭头 `▾` → `▸` | ✅ |
| 再次点击同一组头 | 展开，条目 0 → 2，箭头 `▸` → `▾` | ✅ |
| 点击第二个（已收起）组头 | 展开，条目 0 → 1 | ✅ |
| 收起后组头计数 | 仍显示组内总数 | ✅ |
| 切换标签页后返回 | 折叠状态按日期键保持 | ✅ |
| 置顶页 | 无分组、无组头，直接平铺 | ✅ |
| 分组集合变化（刷新列表） | 用户显式设置的状态按日期键保留 | 逻辑上成立，真机待验 |

1. `cd extension && npm run build`
2. 复制 `dist/` 到临时目录，在 `popup.html` 的 `<script type="module">` 前插入 mock 脚本，注入 `chrome.runtime.sendMessage` 返回固定 `sessions`（需含 `id`、`title`、`pinned`、`updated_at` 秒级时间戳）

4. 用页面内脚本断言：

```js
[...document.querySelectorAll('.date-group')].map((g) => ({
  header: g.querySelector('.date-group-header').textContent.replace(/\s+/g, ''),
```

5. 点击组头前后对比 `count` 是否在 0 与总数之间变化

### 5.3 观察偏差说明（非缺陷）

实测过程中，页面加载最初约 1 秒内曾有两次快速求值读到 `active` 为「置顶」的瞬时状态。经核对源码与编译产物：`activeTab` 初值为 `'normal'`，两个 tab 的 `class` 由 `effect(...)` 同步设置，不存在初始高亮错位。该观察系页面节点尚未完成挂载时过早求值所致，稳定后连续采样 6 秒无闪烁。
