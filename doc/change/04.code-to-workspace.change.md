关键修正：本变更只做「对话 → 文件」这一步，不做通用编辑器，也不涉及任何命令执行。核心只有一件事——**把会话里的代码块还原成工作区文件**。

## 1. 背景与目标

### 1.1 背景

现在的导出链路产出的是**归档**（JSON），不是**可用产物**。用户拿到 JSON 后，要落地一个项目仍得手工翻代码块、逐个复制、自己判断文件名。对话轮次一多就成了纯机械劳动。

链路两侧其实都已就位，缺的只是中间那一步：

| 环节 | 现状 |
|------|------|
| 取会话原文 | ✅ `fetch-hook`（MAIN world）拦截 `history_messages`，`Message.content` 保留 markdown 原文，代码块原样在内 |
| 拉取编排 | ✅ `EXPORT_CURRENT` 消息 + SW 侧重放与限速 |
| 代码块 → 文件 | ❌ 缺 |
| 写本地目录 | ❌ 缺 |

也就是说，本变更不用碰任何网络请求、不用碰 PoW、不用逆向接口——**只做纯文本处理 + 本地写盘**。

### 1.2 目标

1. 从当前会话中提取**全部**代码块（不限于最后一条回复）
2. 自动推断每个代码块的目标文件路径，推断结果**可编辑**
3. 用户显式授权一个本地目录后，按清单写入
4. 目标文件已存在时展示 unified diff，**默认不勾选**，勾选才覆盖
5. 同一路径出现多次时，默认取**最后一次**（视为最终版），可切换
6. 写入结果逐条反馈（成功 / 跳过 / 失败原因），失败不中断整批

### 1.3 非目标

| 项 | 原因 |
|----|------|
| 执行 `pnpm build` / 装依赖 / 跑测试 | 浏览器无进程执行能力；用户明确选择「自己在终端跑」 |
| Agent 循环（自动读文件、自动多轮追问、自动修错） | 需要常驻的本地运行时与工具调用协议，超出浏览器扩展的能力边界 |
| 反向调用 `/api/v0/chat/completion` 自动生成 | 需 PoW 求解 + Bearer Token，违反 ToS 且封号，**明确不做** |
| 代码编辑器 / 文件树 / 语法高亮 | 落盘后交给用户自己的编辑器，本工具不重复造 |
| 二进制 / 图片资源 | 代码块只有文本 |
| 删除本地文件 | 只增改，不删。避免误删事故 |

### 1.4 合规边界

| 项 | 约束 |
|----|------|
| 网络请求 | 不新增任何请求；只消费页面自己发出的响应（与现有导出完全一致） |
| 计费与鉴权 | 不涉及。工具不发起模型请求，不读取 / 不转发 / 不复用任何凭据；对话仍由用户在页面内亲自发起 |
| 本地文件 | 仅写入用户经 `showDirectoryPicker()` 显式授权的目录，且只在该目录之下 |
| 数据外传 | 零上传，代码块不出本机 |
| 用户确认 | 覆盖必须逐项勾选，永不静默改写已有文件 |

## 2. 方案

### 2.1 关键决策（ADR）

| 方案 | 结论 | 理由 |
|------|------|------|
| A. 独立扩展页 `src/studio/studio.html` | **采用** | `chrome-extension://` 页面是顶层文档，满足 File System Access API 的前提；全宽可展示 diff；`FileSystemDirectoryHandle` 存扩展自身源的 IndexedDB，卸载即清干净 |
| B. 放在 popup 里 | 否决 | 点「选择文件夹」的瞬间 popup 失焦关闭，选择器随之取消，物理上不可行 |
| C. 用 `sidePanel` | 否决 | 虽是顶层文档，但默认约 320px 宽，unified diff 完全不可读 |
| D. 注入 chat 页面浮层 | 暂不采用 | 技术可行（content script 在顶层文档，手势有效），但 handle 会存进 `chat.deepseek.com` 的源下，脏；且浮层要处理站点样式冲突。留作 v2 入口增强 |
| E. 由浏览器执行命令 | 否决 | 无此能力；且违背「本地开发环境负责构建」的既定边界 |
| F. diff 用第三方库 | 否决 | 只需行级 LCS，约 80 行自实现即可，与项目零依赖风格一致（参考 `pack-zip.mjs`、`preview.mjs`） |

### 2.2 数据流

```
popup 点「代码落地」
  └→ chrome.tabs.create({ url: studio.html })

studio 启动
  ├→ sendMessage(EXPORT_CURRENT)          ← 复用，不加新消息类型
  ├→ Conversation.messages[].content      ← markdown 原文
  ├→ 切代码块（fence 解析）
  ├→ 推断路径 + 去重（同路径取最后一块）
  ├→ 渲染清单（路径可编辑 / 语言 / 行数 / 是否剪枝过）
  └→ 用户点「选择工作目录」
        └→ showDirectoryPicker({ mode: 'readwrite' })
              ├→ 遍历清单：探测目标文件是否存在
              ├→ 不存在 → 标 NEW，直接写
              └→ 存在   → 读旧内容 → 生成 diff → 默认不勾 → 勾选才写
```

### 2.3 代码块切分

按行扫描 fenced code block，支持 ``` 与 ~~~，取闭合围栏；未闭合的块按「到文末」处理并标记 `unclosed`（提示用户该块可能被截断）。

fence info 解析出三部分：

| 部分 | 例 | 用途 |
|------|-----|------|
| 语言 | `ts` / `tsx` / `python` | 扩展名兜底 |
| 属性 | `title=src/App.tsx` / `file=...` / `path=...` | 最高优先级的路径来源 |
| 其余 | `tsx {1,3-5}` | 忽略（行高亮标记） |

### 2.4 路径推断（按优先级）

| 序 | 规则 | 示例 |
|----|------|------|
| 1 | fence 属性 `title=` / `file=` / `path=` | ` ```ts title=src/App.tsx ` |
| 2 | 代码块首行是路径注释 | `// src/App.tsx` `# app/main.py` `<!-- src/A.vue -->` |
| 3 | 代码块首行是「文件名：」形式 | `src/App.tsx:` |
| 4 | 紧邻上一段正文里唯一的反引号文件名 | 「修改 `src/App.tsx`：」 |
| 5 | 都未命中 | `blocks/01-App.tsx`（序号 + 语言映射扩展名） |

**不做**模糊匹配：宁可落到 `blocks/` 让用户改，也不猜错路径写坏文件。

语言 → 扩展名映射表内置常用项（`ts` `tsx` `js` `jsx` `vue` `py` `go` `rs` `java` `css` `html` `json` `yaml` `md` `sh` `sql`），未知语言用 `txt`。

### 2.5 落盘契约（安全红线）

1. **根域约束**：拼接后的相对路径经 `split('/')` 归一化（消解 `.` / `..` / 空段）后，若出现 `..` 越界或变为绝对路径，整条拒绝并报错，绝不回退到根目录写入。
2. **路径形态**：拒绝以 `/` 开头的绝对路径、拒绝含 `:` 的段（Windows 驱动器）、拒绝含 `\0`。
3. **目录白名单**：目标路径任一段命中 `.git` / `node_modules` / `.preview` / `dist` 时拒绝（防止把生成物写进版本控制的忽略区，也防止覆盖构建产物）。
4. **大小上限**：单文件 512 KB，超出拒绝（防止把整段日志或二进制塞进来）。
5. **只写文本**：一律 UTF-8，不做换行转换（保留原样，避免 Windows CRLF 抖动污染 diff）。
6. **覆盖二次确认**：diff 面板中该行默认不勾；勾选态在写盘前最终再汇总一次。
7. **不删除**：任何情况下不调用 `removeEntry()`。

### 2.6 完整性：三层防线

「让模型输出完整文件」是可行的，也是必做的一层，但不能作为唯一防线。

| 防线 | 手段 | 能解决 | 解决不了 |
|------|------|--------|----------|
| 1. 输出约定 | 在会话消息中约定「输出完整文件，不使用 `// ...` 省略」 | 后续轮次的片段输出 | 已有历史里的片段块；模型概率性失守 |
| 2. 自动检测 | 省略标记 + 行数占比 + 删除占比 | 机械可判定的片段 | 语义完整但基于旧上下文的覆盖 |
| 3. 人工确认 | diff 面板逐项勾选 | 一切需要人判断的情况 | 用户不看就勾 |

**为什么约定不够**（三条，与模型能力无关）：

1. **管不了存量**：本变更导出的是**当前会话全部代码块**。会话前半段是正常聊天，那时没有约定，那些块必然是片段。除非用户从第一句起就按约定格式提问。
2. **管不了本地改动**：模型看不到本地文件的最新内容，只能看到历史上自己写过的版本。即使它 100% 输出完整文件，也会把用户本地手改的几行**静默抹掉**。这条 prompt 无解。
3. **约束力是概率而非契约**：长文件（> 500 行）、上下文临近上限、用户问「概括下思路」时，模型会主动缩写。对「不可逆覆盖」这个操作，2% 的失守率仍然太高。

所以第 2 层才是关键——**片段是可判定的，不需要依赖对模型的信任**：

| 判定信号 | 阈值 | 含义 |
|----------|------|------|
| 省略标记行 | 匹配 `^\s*(//|#|/\*|<!--)\s*(\.\.\.|…|省略|其余不变|rest unchanged|omitted)` | 显式缩写 |
| 行数占比 | 代码块行数 < 目标文件行数 × 30% | 大文件只回了小段 |
| 删除占比 | diff 删除行数 > 目标文件行数 × 50% | 在整体替换而非局部修改 |

命中任一 → 清单打黄标「疑似片段 / 可能覆盖本地改动」，**但不阻断**（有时就是要整体重写）。最终防线是 diff 面板：删了 200 行在一屏里看得见。

#### diff 渲染

自实现行级 LCS，输出 unified 风格（`-` 删除 / `+` 新增 / 空格上下文），上下文 3 行，超出折叠为 `… 共 N 行未变 …`。

#### 更优的落盘模式（v2 备选）

与其逼模型重写全文，不如让它只输出**改动块**：

```
<<<<<<< SEARCH
  旧代码（需逐字匹配）
=======
  新代码
>>>>>>> REPLACE
```

本地做精确匹配替换。好处：不占 token，模型没有省略的动机；SEARCH 块匹配不上会**明确报错**，而不是静默写坏；改动量小，diff 更干净。
成本：模型不遵守格式时整条失败，需要编辑级回退。先不做，等第 2 层积累出真实失守数据再决定。

### 2.7 失败处理

| 场景 | 行为 |
|------|------|
| 没有开着的 chat.deepseek.com 标签页 | 提示「请先打开对话页」，给一个跳转按钮；不静默失败 |
| 会话正文为空（只有提问没有回复） | 提示未找到代码块，不进入目录选择流程 |
| 用户取消目录选择 | 静默返回，清单保留 |
| 权限为 `prompt`（重开浏览器后） | 显示「恢复写入权限」按钮，点击时 `requestPermission({ mode: 'readwrite' })` |
| 持久化 handle 失效（目录被删 / 移动） | 提示重新选择目录，自动清掉旧 handle |
| 单条写入失败（磁盘满、只读） | 该条标红并记录 `error.name`，继续下一条 |
| 整个目录不可写 | 顶部一次性提示，不逐条刷屏 |

## 5. 验证方法

单元测试（`node --test`，与现有测试风格一致）：

1. `blocks.ts` 对 6 种 fence 形态（含 `~~~`、未闭合、带 `title=`、语言未知）的切分结果
2. 路径推断 5 级优先级的命中顺序，且 `blocks/01-App.tsx` 兜底序号连续
3. 同路径出现 3 次时，默认选中最后一块，且清单标注版本数
4. `fs-access.ts` 对 `../../etc/passwd`、`/etc/passwd`、`C:\x`、`.git/config`、`node_modules/x` 全部拒绝
5. `diff.ts` 对「纯新增 / 纯删除 / 交错修改 / 空文件 → 有内容」四类输入的输出

手工验证（真实 Chrome，加载 `dist/`）：

6. 在 chat.deepseek.com 生成一段含 3 个代码块的对话 → popup 点「代码落地」→ studio 列出 3 条，路径合理
7. 首次点「选择工作目录」，选一个空目录 → 3 个文件按路径层级创建成功
8. 改对话内容再跑一次，选同一目录 → 已存在的文件进 diff 面板，默认未勾选；不勾直接写 → 原文件未变
9. 勾选覆盖 → 文件内容更新为代码块内容
10. 关掉浏览器重开 studio → 目录仍在但权限为 `prompt`，点「恢复写入权限」后可继续写
11. 把清单路径改成 `../../../tmp/x.ts` → 该条报错被拒，其余条正常写入
