# 变更提案：Viewer 中英文界面切换

> | 项 | 内容 |
> |----|------|
> | 提案日期 | 2026-10-30 |
> | 影响子项目 | `viewer/`（离线查看器） |
> | 前置变更 | `doc/change/02.i18n-language-switch.change.md`（popup 已完成） |
> | 版本影响 | viewer 无独立版本号；随扩展版本一同发布 |
> | 进度 | ✅ 提案 / ✅ 实施 / ✅ 验证 |

## 1. 背景与目标

### 1.1 背景

popup 的中英文切换已在 v1.0.18 落地（见 `doc/change/02`），但**查看器仍是纯中文**。查阅器是导出的 JSON 的消费端，英文用户导出数据后打开查看器，界面上全是中文，链路并不完整。`doc/change/02` §5.3 已将该项列为「独立子项目，另立变更」，本提案即该变更。

### 1.2 现状（v1.0.18）

| 位置 | 中文文案 | 说明 |
|------|---------|------|
| `src/App.tsx` | 4 处 | 搜索占位符、导入按钮、状态栏两句 |
| `src/components/FileLoader.tsx` | 4 处 | 副标题、拖拽提示、多选提示、加载中 |
| `src/components/ChatView.tsx` | 4 处 | 思考过程折叠、复制原文、未选择会话、空态 |
| `src/components/ConversationList.tsx` | 3 处 | 条目元信息、无匹配、`Untitled` 占位 |
| `src/state.ts` | 1 处 | 加载失败兜底 |
| `src/utils/json-parser.ts` | 5 处 | 4 条校验错误 + 1 条读取失败 |
| `src/utils/date-format.ts` | 6 种 | 今天 / 昨天 / N 天前 / N 周前 / N 个月前 / N 年前 |
| `index.html` | 1 处 | `<html lang="zh-CN">` |

合计约 22 个用户可见文案。`src/utils/markdown.ts` 的中文全为注释，不涉及。

### 1.3 目标

1. 界面文案支持中 / 英，右上角一键切换，无需刷新
2. 语言偏好持久化，下次打开保持
3. 首屏不闪烁（不出现「先中文再变英文」）
4. 已显示的错误提示随语言切换重译
5. 切换时同步 `<html lang>`，利于无障碍与浏览器翻译提示
6. 用户数据（会话标题、消息正文、导出时间）**永不翻译**

### 1.4 非目标

| 项 | 原因 |
|----|------|
| 翻译会话内容 | 用户数据，原样展示 |
| 日期数字格式本地化 | 统一 `YYYY-MM-DD HH:mm`，与导出格式一致，跨语言可对照 |
| 第三种语言 | 字典结构可扩展，本期只做 zh / en |
| 跟随系统实时联动 | 仅在首次访问时用 `navigator.language` 猜默认值，之后以用户选择为准 |
| popup 侧改动 | 已完成，本次不动 |

## 2. 方案

### 2.1 关键决策（ADR）

| 方案 | 结论 | 理由 |
|------|------|------|
| A. 模块级字典 + `lang` signal + `t(key, vars)` | **采用** | 与 popup 一致，同一套心智；JSX 内调用 `t()` 即自动订阅语言变化，无需重建视图 |
| B. 引入 i18next / vue-i18n 等库 | 否决 | 22 个 key，引入依赖与初始化成本不成比例 |
| C. 两套独立页面 / 构建时切换 | 否决 | 无法运行时切换，且违背「一个产物」 |
| D. 语言偏好存 `chrome.storage` | 否决 | viewer 是纯前端页面，无扩展 API；用 `localStorage` |

**持久化**：`localStorage['viewer_lang']`，同步读写，因此首屏不会闪烁（popup 因 `chrome.storage` 是异步接口，才需要 `loadLang().finally(mount)`）。

**默认值**：`navigator.language` 以 `zh` 开头取 `zh`，否则 `en`。理由同 popup：英文 README 的用户打开不该先看到中文。

### 2.2 落点

#### 2.2.1 `src/i18n.ts`（新增）

```ts
export type Lang = 'zh' | 'en';
export const lang = signal<Lang>(detectLang());   // localStorage → navigator.language
export function t(key: string, vars?: Record<string, string | number>): string;
export function setLang(next: Lang): void;        // 写 localStorage + 同步 <html lang>
export function toggleLang(): void;
```

`t()` 与 popup 版本同一实现：查字典、缺失时回退 key 本身、按 `{name}` 插值。`setLang` 额外同步 `document.documentElement.lang`。

#### 2.2.2 切换入口

新增 `LangSwitch` 组件（`src/components/LangSwitch.tsx`），按钮显示**目标语言**（当前中文显示 `EN`，英文显示 `ZH`），用拉丁字母而非汉字——中文「中」在无中文字体的系统会渲染成方框，这是 v1.0.18 截图时实际踩到的。

放置：

- `FileLoader`：标题右上方
- `MainView`：topbar 最右侧

#### 2.2.3 错误提示改为 key + 参数

`json-parser.ts` 目前直接抛中文字符串，`loadError` 存成品文案，切语言后不会变。改为：

```ts
export class ViewerError extends Error {
  key: string;
  vars?: Record<string, string | number>;
}
```

`state.loadError` 改为 `signal<{ key: string; vars?: ... } | null>(null)`，渲染处 `t(loadError().key, loadError().vars)`。未知异常统一落到 `error.loadFailed`。

#### 2.2.4 相对时间

`formatRelativeTime` 内部改调 `t('time.today')` / `t('time.daysAgo', { n })` 等。它在 JSX 表达式里求值，因此自动订阅语言。

### 2.3 key 设计

| 前缀 | 数量 | 示例 |
|------|------|------|
| `app.*` | 4 | `app.searchPlaceholder`、`app.import`、`app.status`、`app.exportedAt` |
| `loader.*` | 4 | `loader.subtitle`、`loader.dropHint`、`loader.multiHint`、`loader.loading` |
| `chat.*` | 5 | `chat.thinking`、`chat.copy`、`chat.noSelection`、`chat.empty` |
| `list.*` | 3 | `list.meta`、`list.noMatch`、`list.untitled` |
| `time.*` | 6 | `time.today`、`time.yesterday`、`time.daysAgo`、`time.weeksAgo`、`time.monthsAgo`、`time.yearsAgo` |
| `error.*` | 6 | `error.missingMeta`、`error.invalidMeta`、`error.badConversations`、`error.badJSON`、`error.readFailed`、`error.loadFailed` |
| `lang.*` | 2 | `lang.switchToEn`、`lang.switchToZh` |

合计 30 个 key。

## 3. 契约与边界

| 场景 | 行为 |
|------|------|
| 首次访问 | 按 `navigator.language` 决定，不写 localStorage（用户未表态） |
| 手动切换 | 写入 `localStorage['viewer_lang']`，同步 `<html lang>` |
| 刷新页面 | 读 localStorage，直接以目标语言渲染，无闪烁 |
| 已显示错误 + 切语言 | 错误文案跟着变（存 key 而非成品字符串） |
| 会话标题 / 消息内容 | 原样展示，不翻译 |
| `Untitled` 占位 | 中文「无标题」/ 英文 `Untitled` |
| 日期与时间 | 保持 `YYYY-MM-DD HH:mm` |
| 字典缺 key | 回退显示 key 本身，便于发现遗漏 |
| `localStorage` 不可用（隐私模式） | try-catch 兜底，降级为仅本次会话生效 |
| 语言相关字面量 | 不得在 `map` 回调体内提前求值 `t()`（plain 陷阱，同 popup 契约） |
| 原生元素属性 | 直接传表达式（`placeholder={t('k')}`），**不得传函数**——函数不会被解析，会被字符串化后写进属性，界面上直接显示出函数源码（实施阶段实测踩到，见 §4.2） |

### 4.2 执行记录

**构建**：`tsc --noEmit` 无错；`pnpm build` 通过（CSS 7.69 kB / JS 1067 kB）。

**浏览器实测**（vite preview + playwright，9 步全部通过）：

| # | 场景 | 结果 |
|---|------|------|
| 1 | 首屏（headless `navigator.language` 为 en-US） | 英文，`<html lang>=en`，`localStorage` 未写入（用户未表态） |
| 2 | 点切换改中文 | 全部文案转中文，`<html lang>=zh-CN`，存入 `viewer_lang=zh` |
| 3 | 导入损坏 JSON | 「无效的导出文件：缺少 export_meta 字段」 |
| 4 | 损坏提示存在时切英文 | 重译为 "Invalid export file: missing export_meta" |
| 5 | 导入正常 JSON（英文态） | 状态栏「3 conversations · 2 messages · Exported: …」；列表「2 messages · today」「Untitled」「2mo ago」 |
| 6 | 切中文 | 「共 3 个会话 · 2 条消息 · 导出时间: …」「2 条消息 · 今天」「无标题」「2个月前」；placeholder 与按钮 title 同步 |
| 7 | 搜索不存在的关键词 | 「没有匹配的会话」 |
| 8 | 刷新 | 语言保持中文，`<html lang>` 同步 |
| 9 | 切英文后刷新 | 语言保持英文 |

**实施中的发现（与预期相反）**：最初把会随语言变化的属性写成函数形式
`placeholder={() => t('app.searchPlaceholder')}`，想利用 `MaybeGetter`；实测 placeholder 被渲染成
`()=>j("app.searchPlaceholder")` 直接显示在输入框上。原因：`MaybeGetter` 只对**组件 props** 生效，
原生元素会直接把函数 `String()` 化后写进属性。改为直接传表达式后，placeholder 与按钮 `title`
均能随语言正确更新（plain 在 effect 内求值属性表达式）。结论已写入 SDD §5.3。

**文案守卫**：除 `i18n.ts` 字典与注释外，`src/` 仅剩 1 处中文——`ChatView.tsx` 的
`console.error('复制失败:', error)`，属开发者控制台日志、非用户可见，有意保留。

## 5. 验证方法

1. 类型检查与构建：`cd viewer && npx tsc --noEmit && pnpm build`
2. 文案守卫（除注释与字典外，`src/` 不应再有中文字面量）：

```bash
grep -rnP "['\"\`][^'\"\`]*[\x{4e00}-\x{9fa5}]" viewer/src --include=*.tsx --include=*.ts \
  | grep -v "i18n.ts"
```

3. 运行时验证：`pnpm build && pnpm preview`，浏览器打开后：
   - 加载页文案随语言切换
   - 导入一份导出 JSON，检查侧栏 / 状态栏 / 聊天区 / 相对时间
   - 导入一个损坏的 JSON，确认错误提示切语言后重译
   - 刷新页面确认语言保持，且 `<html lang>` 已同步
4. 空态验证：搜索一个不存在的关键词，确认「没有匹配的会话」
