## 1. 变更提案（需求背景）

### 1.1 背景与动机

popup 自 v1.0.12 重构为「会话管理器」后，界面文案全部是硬编码中文：标题栏、状态、标签页、工具栏、按钮、空态、进度提示、确认弹窗、日志面板，约 60 处用户可见字符串，全部散在 `App.tsx` 里。`popup.html` 中出现的 8 行中文均为 CSS 注释，与界面无关。

README 提供中英双语，扩展本身却只有中文。对英文读者而言：能看懂 README、能装扩展，打开后不认识「置顶 / 非置顶 / 导出选中 / 删除确认」。这是一个真实的可用性缺口，而非美化项。

同时，用户在 README 补充截图时直接提出了这个需求：

> 截图发现，还需要有个中英文切换的功能才是。

注意措辞是「切换」，不是「跟随系统」——需求的可验证形态是：**界面上有入口，点一下，整屏文案在两种语言间变化**。

### 1.2 现状结论

| # | 事实 | 核实方式 |
|---|------|----------|
| 1 | 扩展无任何 i18n 设施：无 `_locales/` 目录，`manifest.json` 无 `default_locale`，源码无 `chrome.i18n` 调用 | `grep -rn "_locales\|chrome.i18n\|default_locale"` 无命中 |
| 2 | 用户可见文案集中在 `App.tsx`，约 60 处；`popup.html` 无可见文案 | 正则提取 + 人工核对 |
| 3 | `manifest.json` 的 `name` / `description` 为英文（`DeepSeek Chat Exporter`），无需翻译 | 读清单 |
| 4 | 日期标签（今天 / 昨天 / 周X / 日期未知）由 `formatDayLabel` 生成，已被 `dateGroups` computed 使用 | `App.tsx:135-148` |
| 5 | 运行日志正文由 service worker 与 content 脚本产出（中文），popup 只负责展示 | `utils/logger.ts`、`service-worker.ts` |

结论：需要一个**运行时可变**的语言状态，且文案取值必须放在响应式上下文里，否则切换后界面不会重绘（这正是 v1.0.16 折叠失效踩过的同一个坑，见 `doc/bugfix/02`）。

### 1.3 变更目标

| # | 目标 |
|---|------|
| 1 | popup 提供语言切换入口，点击后**整屏文案立即变化**，无需重开 popup |
| 2 | 支持中文（`zh`）与英文（`en`）两种语言 |
| 3 | 选择持久化到 `chrome.storage.local`，下次打开 popup 保持 |
| 4 | 首次使用时按浏览器 UI 语言猜一个默认值（`zh*` → 中文，其余 → 英文） |
| 5 | 日期分组标签随语言变化：`今天 / 昨天 / 10-27 周二` ↔ `Today / Yesterday / 10-27 Tue` |
| 6 | 不改变任何功能行为：列表、勾选、导出、删除、日志的全部逻辑与 DOM 结构保持不变 |

### 1.4 影响范围

**做：**

- popup 全部静态 UI 文案：标题栏、连接状态、删除接口状态、标签页、工具栏、列表空态 / 加载态、三个主按钮、进度区、提示消息、诊断面板标题、日志面板外壳、删除确认弹窗、条目内的置顶徽标与占位标题
- 日期与周几标签
- 语言偏好持久化与默认值检测

**不做（本期明确排除）：**

| 项 | 理由 |
|----|------|
| 运行日志正文 | 由 SW / content 产出并已持久化在 storage，历史日志是中文的；翻译它们需要改动 3 个文件近百处文案，且混合语言日志更难排查。诊断信息保持原文更合适 |
| service worker / content script 的 `chrome.notifications`、错误提示 | 这些文案多数经日志与状态字段回流到 popup，属上一条范畴 |
| 下载文件名、导出的 JSON 结构 | 与语言无关，改动会破坏下游兼容性 |
| viewer 子项目 | 独立的展示端，有自己的构建与发布节奏，另立变更 |
| 数字 / 日期格式本地化（`2026-10-30 12:39` → `Oct 30, 2026 12:39 PM`） | 属格式化层改动，与「文案翻译」是两件事；保持 ISO 风格更易读、更易排序 |
| `manifest.json` 的 `name` / `description` 多语言 | 需 `_locales` 静态机制，与运行时切换目标不一致，且当前已是英文 |

### 1.5 风险评估

| 风险 | 等级 | 说明与缓解 |
|------|------|-----------|
| 切换后界面不重绘 | 中 | 与折叠 bug 同源。缓解：`t()` 内部读 `lang` signal，且**只在 JSX 表达式或 computed 内调用**；实施后必须做真实浏览器点击验证，不能只看类型检查 |
| 已发出的提示消息不跟随切换 | 低 | 消息是快照字符串（切语言前发出的仍是旧语言）。可接受：下次操作自然用新语言。若要求实时重译，需把消息改成 key + 参数存储，成本更高且收益低 |
| 语言偏好读写失败（storage 异常） | 低 | `try-catch` 包裹，失败时回退回默认语言，不阻塞 popup 渲染 |
| 首屏语言闪烁（默认 zh → 读到 en 后切换） | 低 | `main.tsx` 改为「先 `await loadLang()` 再 mount」，读 storage 仅毫秒级 |
| 文案遗漏（新增功能忘了走 `t()`） | 中 | §3.1 立契约；构建后用脚本扫描 `App.tsx` 中新增的中文字面量作为守卫 |
| 英文文案过长导致按钮换行 / 溢出 | 中 | 英文比中文长 1.5-2 倍，需在真实浏览器里检查三个主按钮、标签页、工具栏的宽度；必要时缩短英文措辞（如 `Export selected` → 保持两词内） |

### 1.6 验收标准

| # | 验收项 | 判定方式 |
|---|--------|----------|
| 1 | 点击切换控件，整屏文案在 zh / en 间切换 | 逐屏人工核对 + DOM 文本断言 |
| 2 | 切换后立即生效，无需重开 popup | 同一次会话内连续切换 3 次 |
| 3 | 重开 popup 后保持上次选择 | 关闭再点开，或 `chrome.storage.local.get('ui_lang')` 校验 |
| 4 | 首次使用按浏览器语言取默认值 | 清空 storage 后，zh 系统 → 中文、en 系统 → 英文 |
| 5 | 日期分组标签随语言变化 | `今天` ↔ `Today`、`周二` ↔ `Tue`、`日期未知` ↔ `Unknown date` |
| 6 | 占位符插值正确 | `导出选中 (3)` ↔ `Export selected (3)`、`已选 2/5 · 共 3` ↔ `2/5 selected · 3 total` |
| 7 | 无功能回归 | 列表加载、折叠、勾选、导出、删除、日志、诊断均与 v1.0.17 一致 |
| 8 | 英文下无截断、无溢出 | 真实浏览器 380px 宽 popup 内检查 |

## 2. 技术方案

### 2.1 方案对比（ADR）

**方案 A：`chrome.i18n` + `_locales/{zh,en}/messages.json`（否决）**

这是 Chrome 扩展的官方机制，但有一个致命限制：`chrome.i18n.getMessage()` 的结果跟随**浏览器 UI 语言**，在运行时不可变。用户明确要的是「切换」，而官方机制只能做到「跟随系统」，且切换浏览器语言需要重启浏览器。

结论：机制与需求不匹配，否决。但它仍适合 `manifest.json` 的 `name` / `description` 多语言，本期不需要。

**方案 B（采用）：模块级字典 + plain signal**

```ts
const lang = signal<Lang>(detectInitialLang());
const dicts: Record<Lang, Dict> = { zh, en };

function t(key: string, vars?: Record<string, string | number>): string {
  const template = dicts[lang()][key] ?? key;
  return vars ? template.replace(/\{(\w+)\}/g, (_, k) => String(vars[k] ?? '')) : template;
}
```

要点：

1. `t()` 内部读 `lang()`，任何在 JSX 表达式 / computed / when getter 内调用 `t()` 的地方都会自动订阅语言变化
2. 字典是纯对象，无运行时依赖，构建体积增量约 6KB（未压缩）
3. 与项目现有响应式风格一致，不需要引入第三方 i18n 库

**方案 C：把字典挂在 props 上逐层传递（否决）**

组件树只有 5 层，但每个叶子组件都要多一个 `lang` 参数，且 `formatDayLabel` 这类纯函数无法接受 props，改动面反而更大。

**方案 D：切换即 `location.reload()`（否决）**

实现最省事，但 popup 重载会丢失当前列表、勾选与提示消息，且用户能感知到闪白，体验差。

### 2.2 落点与实现

#### 2.2.1 字典与取值函数

新增 `extension/src/popup/i18n.ts`（只服务 popup，不进 SW / content，避免把 plain 依赖带进 service worker）：

| 导出 | 职责 |
|------|------|
| `type Lang = 'zh' \| 'en'` | 语言枚举 |
| `lang` | 当前语言 signal |
| `t(key, vars?)` | 取文案 + `{name}` 占位符插值；未命中 key 时原样返回 key（便于发现遗漏） |
| `setLang(next)` | 写 signal + 持久化到 `chrome.storage.local` |
| `loadLang()` | 启动时读 storage，失败静默回退 |

字典按模块分组命名 key：`app.*`（标题栏与状态）、`list.*`（标签页与工具栏）、`item.*`（条目内）、`date.*`（日期标签）、`action.*`（主按钮）、`progress.*`、`msg.*`（提示消息）、`logs.*`、`diag.*`、`modal.*`、`lang.*`。总计约 62 个 key。

#### 2.2.2 语言状态与持久化

- 存储：`chrome.storage.local`，key = `ui_lang`，值 `'zh' | 'en'`
- 默认：`chrome.i18n.getUILanguage()` 以 `zh` 开头 → `zh`，否则 `en`
- 启动：`main.tsx` 由 `mount('#app', App())` 改为先 `await loadLang()` 再 `mount`，规避首屏语言闪烁

#### 2.2.3 切换入口

放在标题栏右侧、连接状态徽标左侧，一个胶囊按钮：

```tsx
<div class="header-right">
  <button class="lang-switch" title={t('lang.switchTitle')} onClick={toggleLang}>
    {lang() === 'zh' ? 'EN' : 'ZH'}
  </button>
  <div class="status">...</div>
</div>
```

按钮显示的是**目标语言**（当前中文则显示 `EN`，当前英文则显示 `ZH`），点一下切过去，符合「开关」直觉。`title` 提示当前动作。

注意：目标语言用拉丁字母 `ZH` 而非汉字「中」——英文系统往往没有中文字体，汉字会渲染成方框（截英文图时已实际碰到过）。`popup.html` 新增 `.header-right`（flex + gap）与 `.lang-switch`（11px、1px 边框、圆角、hover 变色）。

#### 2.2.4 日期与周几

`formatDayLabel(key)` 改为读 `t()`：

| 语言 | 今天 | 昨天 | 其它 | 未知 |
|------|------|------|------|------|
| zh | 今天 | 昨天 | `10-27 周二`（跨年补 `2025-10-27 周二`） | 日期未知 |
| en | Today | Yesterday | `10-27 Tue`（同上） | Unknown date |

因为该函数在 `dateGroups` computed 内被调用，语言变化会自动触发分组重算，标签随之更新——不需要额外处理。

`WEEK_NAMES` 拆成 `{ zh: [...], en: [...] }` 两组常量。

#### 2.2.5 文案迁移清单（按区域统计）

| 区域 | key 前缀 | 条数 | 代表项 |
|------|----------|------|--------|
| 标题栏与状态 | `app.*` | 7 | 已连接 / 未连接 / 删除接口 / 已学习 |
| 标签页与工具栏 | `list.*` | 10 | 置顶 (n) / 非置顶 (n) / 全选本页 / 刷新列表 / 暂无会话 |
| 列表条目 | `item.*` | 3 | 置顶徽标 / 徽标 title / 无标题 |
| 日期标签 | `date.*` | 4 | 今天 / 昨天 / 周X / 日期未知 |
| 主按钮 | `action.*` | 3 | 导出当前会话 / 导出选中 / 删除选中 |
| 进度 | `progress.*` | 3 | 导出中… n% / 正在导出 i/t：title / 保持页面开启 |
| 提示消息 | `msg.*` | 14 | 已加载 n 个会话 / 导出失败 / 删除完成 |
| 日志面板 | `logs.*` | 13 | 运行日志 / 刷新 / 下载日志 / 拷贝 / 清空 |
| 诊断面板 | `diag.*` | 1 | API 捕获诊断 (n) |
| 确认弹窗 | `modal.*` | 3 | 删除确认 / 取消 / 确认删除 |

#### 2.2.6 样式

`popup.html` 追加两段：`.header-right`（`display:flex; align-items:center; gap:6px`）与 `.lang-switch`（`height:20px; padding:0 6px; font-size:11px; border:1px solid #e5e7eb; border-radius:4px; background:#f9fafb; color:#6b7280; cursor:pointer`，hover 时边框与文字转为蓝色）。强调：不改动既有任何选择器。

### 2.3 设计取舍

| 议题 | 结论 | 理由 |
|------|------|------|
| 官方 `_locales` vs 自研字典 | 自研字典 | 官方机制运行时不可变，无法满足「切换」 |
| 按钮显示当前语言 vs 目标语言 | 显示目标语言 | 点击即「切到 EN / 切到中文」，动作与文案一致 |
| 语言状态放模块级 vs 组件内 | 模块级 | 与 `activeTab` / `groupExpanded` 一致；popup 生命周期短，无需卸载清理 |
| 提示消息是否实时重译 | 不重译 | 消息是快照；重译需改成 key+参数模型，收益低 |
| 日志正文是否翻译 | 不翻译 | 诊断信息保持单一语言更利于排查与搜索 |
| 默认语言来源 | 浏览器 UI 语言 | 比固定 zh 更合理；首次即符合多数用户预期 |
| 日期数字格式是否本地化 | 不本地化 | `YYYY-MM-DD HH:mm` 无歧义、可排序、与导出 JSON 一致 |

## 3. 增量规范（实施后契约）

### 3.1 文案契约

| # | 规则 |
|---|------|
| 1 | popup 内一切用户可见文案必须经 `t()` 取值；禁止新增中文字面量直接进 JSX |
| 2 | `t()` 的调用位置必须在 JSX 表达式、`computed` 或 `when` getter 内——**不得**在 `map` / `each` 回调体内求值后赋给 `const`（否则切换语言不重绘，同 v1.0.16 折叠缺陷） |
| 3 | key 采用 `模块.语义` 小驼峰，模块前缀固定为 §2.2.5 的 11 组 |
| 4 | 占位符统一用 `{name}` 形式，中英文必须使用同一组占位符名 |
| 5 | 中文文案标点用全角，英文文案标点用半角；英文首字母大写、其余小写（按钮除外，按 Title Case 的仅用于面板标题） |
| 6 | 未命中的 key 原样返回，便于在真机上发现遗漏 |

### 3.2 边界条件矩阵

| 场景 | 期望行为 |
|------|----------|
| 首次使用（storage 为空，浏览器 zh-CN） | 中文 |
| 首次使用（storage 为空，浏览器 en-US） | 英文 |
| 用户切到英文后关闭 popup 再打开 | 英文 |
| `chrome.storage.local` 读失败 | 回退默认语言，popup 正常渲染，不报错 |
| `chrome.storage.local` 写失败 | 当前会话内仍生效，仅下次打开回到旧值；不弹错误提示 |
| 列表为空时切换语言 | 空态文案同步变化 |
| 列表加载中切换语言 | 「正在加载… 已加载 n 条」同步变化 |
| 折叠某分组后切换语言 | 折叠状态保持，组头标签跟随语言 |
| 导出进行中切换语言 | 进度标题与百分比同步变化 |
| 切换语言时确认弹窗打开 | 弹窗内文案同步变化（`confirmText` 是 key+参数模型时） |
| 提示消息已显示后切换语言 | 已显示的消息保持旧语言（快照），下次操作使用新语言 |
| 语言键缺失 | 显示 key 本身，不崩溃 |

### 3.3 插值与复数

本期采用「无复数变形」策略：英文用 `{n} sessions` / `{n} session` 之外的统一写法（如 `3 selected`、`Selected (3)`），避免引入 ICU 复数规则。理由是 popup 的计数量词少且语境明确，`Selected (1)` 与 `Selected (3)` 均自然。
